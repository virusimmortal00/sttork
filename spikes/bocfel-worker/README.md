# Bocfel worker build spike

ADR-0009 retains this as historical oracle/fallback work after selecting Dork as
the primary TypeScript candidate. It is not the active production path.

Status: isolated M0 build scaffold; experimental and non-release

This directory contains only project-owned orchestration, build configuration,
tests, and exact transformation instructions. It never vendors an interpreter,
RemGlk, Emglken, a generated JavaScript/WebAssembly artifact, a conformance
story, or a Zork asset. Every fetched and generated byte stays in a
caller-created temporary directory outside the repository.

At the time it was created, the scaffold advanced the source-closure work in
ADR-0006 without changing that ADR or any gate status. It builds exactly one
`bocfel-noz6` target from:

- the official Bocfel 2.5.1 archive, authenticated by SHA-256;
- RemGlk at one full commit and tree ID; and
- four selected MIT Emglken inputs at one full commit and tree ID.

The aggregate Emglken npm package is never installed. Garglk is never fetched,
`static-patches.h` is rejected, and the CMake graph has no Scare or TADS target.
All immutable identities and selected-file hashes are in `source-lock.json`.

## `pb-imgsize` boundary

RemGlk normally uses `pb-imgsize` to discover JPEG/PNG dimensions. Version 0.2.5
does not carry the complete notice required for redistribution review. For this
no-Z6, version-3-only experiment, the `remglk-no-image-metadata-v1`
transformation removes both the dependency and the metadata-reading block. The
harness then rejects a transformed Cargo lock, manifest, resolved dependency
tree, or source closure that still contains the dependency.

Transformations are not contextual patch files and contain no copied upstream
source block. Each operation identifies a byte range by offset, length, and
SHA-256. The harness authenticates the complete input file and every removed or
replaced segment, applies all operations, and authenticates the complete output
file. A moved, missing, partial, extra, or stale transformation cannot be
silently accepted.

The tradeoff is explicit: image dimensions parsed from Blorb data remain zero.
That is within the repository-owned V3 fixture and initial Zork I-III scope, but
it is not accepted for a broader interpreter profile. Broader story-version or
graphics work must obtain an authoritative `pb-imgsize` notice or replace this
transformation with a reviewed, tested feature boundary.

## Opt-in build

The scaffold requires all of the following before it makes a network request:

- an existing, empty, nonsymlink temporary directory outside the repository that
  is owned by the current user and is not group- or world-writable;
- resolved parent directories that cannot be used by another user to replace the
  work-directory path (a sticky system-temp parent is accepted when its
  protected child belongs to the current user);
- both `--allow-network` and `--allow-build`; and
- the exact local Docker image ID in `source-lock.json`, on its recorded
  `linux/arm64` platform.

The archive request uses manual redirects, permits only the pinned HTTPS origin,
and reads exactly the pinned compressed byte length. The harness then
authenticates the whole archive before parsing it, bounds decompression, and
requires the pinned uncompressed length, member counts, and complete
content-and-type shape. It extracts directly from that inspected in-memory tar
model; the host `tar` program and `TAR_OPTIONS` are never used. Material members
may be only prior-parented directories and single-link regular files below the
one archive root. Symlinks, hard links, devices, FIFOs, path overrides, GNU
extensions, duplicate/case-colliding paths, and traversal are rejected. The one
recorded global PAX comment is metadata only and is never extracted.

Git and Docker subprocesses receive explicit allowlisted environments rather
than the host environment. Git system/global configuration, templates, hooks,
interactive prompts, non-HTTPS transports, and redirects are disabled. Docker
uses a newly created empty config directory inside the work directory; the
host's `HOME`, Docker config/plugins, Git injection variables, dynamic-loader
variables, and Node options are not inherited. Only tool lookup, certificate,
proxy, and an optional canonical local Unix Docker socket cross the boundary;
remote Docker transports are rejected because local bind mounts are required.
Selected source files and transformation targets must have link-free parent
paths and open as the same single-link regular-file inode that was inspected.

On the machine that produced the dated disposable spike:

```sh
work_directory="$(mktemp -d /private/tmp/zv-bocfel-worker.XXXXXX)"
node spikes/bocfel-worker/build.mjs \
  --work-dir "$work_directory" \
  --allow-network \
  --allow-build
```

The command leaves sources, Cargo downloads, build intermediates, artifacts, a
resolved `cargo-tree.txt`, and `build-result.json` in that temporary directory.
It never cleans or overwrites a directory, so a failed run remains available for
inspection and a rerun must use a new empty directory.

The work-directory inode is rechecked around downloads and the Docker build.
These checks narrow path-replacement races, but a caller-owned directory is not
a sandbox against that same caller deliberately modifying it concurrently. Use
the private `mktemp -d` directory shown above and do not share it with another
process while the harness runs.

The pinned local builder image is evidence from one experiment, not a portable
release toolchain: its Rust installation came through an upstream mutable
`rustup` shell installer. Consequently, this command is intentionally not a root
package script, CI job, gate result, or release command. A later acceptance
harness must pin the complete builder supply chain and generate the artifact
SBOM and notice bundle.

## Hermetic validation

The small validation suites make no network, Docker, Cargo, or compiler calls:

```sh
pnpm exec vitest run \
  spikes/bocfel-worker/harness.unit.test.mjs \
  spikes/bocfel-worker/harness.contract.test.mjs
```

The repository-wide `pnpm test` command also discovers these tests. They cover
argument consent, work-directory isolation, path traversal, hash/ref and
transformation mismatch, hostile subprocess environments, redirect and body
limits, unsafe tar member types and links, selected-file links, the forbidden
Cargo closure, and the one-target/no-static-patch CMake contract.

## What this does not prove

Successful output is still an experimental candidate. This scaffold does not
produce a generated SBOM or complete notice bundle, pin the mutable Rust
installer used by the local builder, implement the production worker codec, or
run the six historical ADR-0006 acceptance gates. Generated artifacts must not
be copied into the repository or released.
